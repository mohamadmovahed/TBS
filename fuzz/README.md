# Fuzzing

The parsers in `tbsdvb` and `tbsbbproc` process data received off the air, so they
must survive any input. Six libFuzzer targets cover them:

| Target | What it exercises |
|---|---|
| `fuzz_bbframes` | BBFrames into `tbs::bb::Processor`: stream detection, TS recovery, PSI/SI, GSE, IP statistics, reports |
| `fuzz_pseudots` | Raw bytes as (pseudo-)TS: TS alignment, BBFrame reassembly, BBFrame→TS, PSI/SI |
| `fuzz_psi` | PSI/SI section parsers, sections both packetised and direct |
| `fuzz_gse` | GSE decapsulation (normal/HEM), extension headers, IP statistics, pcap writer |
| `fuzz_dvbtext` | DVB text decoding |
| `fuzz_capture` | Capture-file format detection and BBFrame resynchronisation |

The BBHeader CRC-8 and the section CRC-32 are filled in by the harnesses, so random
input reaches the deep parsers instead of failing the checksum.

## Running

```sh
cmake -S . -B build-fuzz -DTBS_BUILD_FUZZERS=ON -DTBS_BUILD_GUI=OFF -DTBSDVB_ENABLE_ZMQ=OFF \
      -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++ -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build-fuzz -j
mkdir -p work && cp fuzz/corpus/gse/* work/
./build-fuzz/fuzz/fuzz_gse -max_total_time=600 work      # ASan + UBSan are built in
ctest --test-dir build-fuzz -R fuzz-regress               # replay corpus + regressions
```

On Debian/Ubuntu, libFuzzer comes with `clang` and `libclang-rt-<ver>-dev`. With a
compiler other than Clang, the targets are built with `standalone_main.cpp` and
only replay the files.

`corpus/` holds the seed inputs, generated by `tbs-fuzz-gen-corpus fuzz/corpus`.
`regressions/` holds inputs that crashed an earlier version. When a fuzzer finds a
crash, fix it and add the crash file there.

## Findings so far

The first run found four memory-safety bugs in the PSI analyser. A section of a
long-form table (PAT, CAT, PMT, NIT, SDT, BAT, EIT) with the section-syntax bit
cleared skipped the CRC and length checks, and the parsers then underflowed `len - 4`.
Such sections are now rejected, and each parser has a minimum-length guard. The
reproducers are in `regressions/`.
